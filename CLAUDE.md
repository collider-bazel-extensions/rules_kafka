# rules_kafka

Bazel rules for Apache Kafka in tests:
- a per-test single-node KRaft broker (`kafka_server`, `kafka_server_health_check`, `kafka_test`), on the Apache binary release and rules_java's remote JDK 21;
- a cluster install over Bitnami's pre-rendered chart (`kafka_install`, `kafka_health_check`, via rules_kubectl).

The per-test broker follows rules_valkey's `valkey_server` shape and rules_zap's JDK handling; see DESIGN.md (decisions 16-35).

## Commit requirements

- All tests must pass before any commit with code changes: `bazel test //tests/...` (analysis + per-test broker tests, no container runtime). Run the kind smoke `bazel test //tests:smoke_test` too when install code changes.
- All documentation (`README.md`, `DESIGN.md`, `CLAUDE.md`) must be updated to reflect any code changes before committing: new rules, changed attributes, new public API surface, behaviour changes.
- Never commit `bazel-*`, `MODULE.bazel.lock` or `__pycache__`.

## Key concepts

- **Laziness.** `@kafka_dist` and `@remotejdk21_*` are only fetched when a kafka_server is built. Don't load anything from those repos in `defs.bzl`; refer to them by label only.
- **Kafka's scripts.** `kafka-server-start.sh` → `exec kafka-run-class.sh` → `exec java`, so the Popen pid is the JVM. The scripts `mkdir -p $LOG_DIR` (default in the distribution): always set `LOG_DIR`. `KAFKA_JMX_OPTS` empty → JMX agent on: always set it. `EXTRA_ARGS` replaces `-name kafkaServer -loggc`.
- **No writes outside `$TEST_TMPDIR`.** `-XX:-UsePerfData` (else `/tmp/hsperfdata_<user>/<pid>`), `-Djava.io.tmpdir`, `LOG_DIR`.
- **Processes.** Each JVM in its own session + `PR_SET_PDEATHSIG`. Stop = SIGTERM by pid, 30 s, SIGKILL by group. Find strays with `pgrep -u $(id -u) -a java` and kill by PID; never `pkill -f` (the pattern matches the shell running it).
- **Kafka 4.x CLI flags.** `--command-property` (was `--producer-property` / `--consumer-property`), `--reader-property`, `--formatter-property`. The consumer refuses `--from-beginning` with `--partition`/`--offset`.

## Development

```sh
bazel test //tests/...                                   # analysis + broker tests (no container runtime)
bazel test //tests:roundtrip_test --runs_per_test=4       # parallel brokers
systemd-run --scope --user --property=Delegate=yes -- \
    bazel test //tests:smoke_test --test_output=streamed  # kind (podman)
tools/update_versions.sh [<version>] [--check]            # Kafka pin
bash tools/render_kafka.sh 32.4.3                         # re-render the chart manifest
.github/consumer/check.sh /tmp/<scratch>                  # consumer checks against `git archive HEAD`
```

## Known limitations

- `python3` is required on the host for the launcher.
- PLAINTEXT only (no SASL/TLS); one node; one Kafka version per build.
- On macOS a SIGKILLed launcher can leave the broker JVM running (no `PR_SET_PDEATHSIG`); SIGTERM/SIGINT stop it cleanly everywhere.
- `kafka_test` wraps `sh_test`; other languages use `kafka_server` through rules_itest.
